# 明日方舟工具箱

一个 AstrBot 插件，把《明日方舟》的几件日常小事装在一起：**换班提醒、公开招募计算、森空岛签到、MAA 远程启动**。四个功能各自独立开关，**默认只开最安全的两个**。

---

## 它解决什么

基建换班靠脑子记，结果就是干员心情见底了才想起来。这个插件按你自己填的三班时刻，在每班换班前推一条提醒给你。

**提醒这一部分不需要登录你的游戏账号，也不需要 MAA**——即使你不装任何辅助工具、甚至游戏不在运行，提醒照样到。

插件里另外几个功能是这样：**公开招募计算**默认开启，纯本地计算、不联网、不需要账号；**森空岛**默认关闭，开了会用你的账号，**而且能代你每日签到**；**MAA 远程控制**默认关闭，开了需要你在自己的电脑上配两个地址。**会用你账号或需要你额外配置的那两个，都不是默认开着的**——但既然插件里带着它们，这里就说清楚。

## 安装

**从插件市场装（推荐）**

在 AstrBot WebUI 的「插件市场」里搜索 `明日方舟工具箱`，点安装。

**手动装**

把仓库克隆到 AstrBot 的插件目录，然后重启 AstrBot：

```bash
cd /path/to/astrbot/data/plugins
git clone https://github.com/ppepperkok-hue/astrbot_plugin_arknights_toolbox.git
```

## 功能与开关

| 功能 | 默认 | 打开之后需要你做什么 |
| --- | --- | --- |
| 基建换班提醒 | **开** | 发 `/ak bind` 绑定会话，再按下面「配置」一节填三班时刻 |
| 公开招募计算 | **开** | 不用做什么，直接发指令就能用 |
| 森空岛（签到 / 状态） | 关 | 打开后发 `/ak skland login` 扫码授权 |
| MAA 远程控制 | 关 | 打开后照 [MAA 接入指南](docs/guides/maa-remote-control.md) 在你电脑上填两个地址 |

**开关在哪**：AstrBot 面板 → 插件配置 → **明日方舟工具箱** → 第一项「**模块开关**」。四个开关都在那里面，每个都带一句说明。

**关掉的模块不会注册任何指令、也不会注册任何定时任务。** 所以关着的时候发对应指令，会收到「未知子命令」——**多半就是那个开关还没打开，不是插件坏了**。

> 如果你在配置页里**根本看不到「模块开关」这一项**（不同 AstrBot 版本对嵌套配置的渲染不完全一致），那是缺陷，欢迎到仓库提 issue 说明你的 AstrBot 版本。这种时候森空岛与 MAA 在**面板上**打不开，只能去插件的配置文件里手工写 `modules.skland` / `modules.maa`；另外两个功能不受影响。

## 配置

装好后在 WebUI 的插件配置页里填这几项。**改班次更方便的办法是插件页面**（见下一节），那里是拖时间轴，不用自己算 24 小时。

**三班时刻**——每一项都是「班次名称 / 开始时刻 / 时长（小时）」：

| 配置项 | 说明 | 默认 |
| --- | --- | --- |
| `shift_1_name` / `shift_1_start` / `shift_1_hours` | 第一班 | 第 1 班 / 08:00 / 12 |
| `shift_2_name` / `shift_2_start` / `shift_2_hours` | 第二班 | 第 2 班 / 20:00 / 6 |
| `shift_3_name` / `shift_3_start` / `shift_3_hours` | 第三班 | 第 3 班 / 02:00 / 6 |
| `lead_minutes` | 提前多少分钟提醒 | 10 |
| `timezone` | 时区（IANA 名称） | `Asia/Shanghai` |

> **班次名为什么用「第 N 班」而不是「早班/晚班」**：你导入的排班表里，班次顺序是按**下标**对应的（`Shift 1` / `Shift 2` / `Shift 3`），而「早/晚/夜」这种标签是人为贴的，**跟排班表没有任何对应关系**——一改作息就会对不上，**而插件仍会照着一个错的名字去取干员**。所以默认用**位置名**，顺序与排班表一致（**12 / 6 / 6**，已是默认）。若你的排班表时长顺序不同，导入时插件会**指名道姓地提示**你哪几班对不上。

> **两个硬性要求**：三段时长之和必须**正好 24 小时**；而且必须**首尾相接**——上一班的开始时刻加上时长，正好等于下一班的开始时刻。
>
> 不符合的话插件会**拒绝加载**，并在日志里明确告诉你哪里断了。这是故意的：宁可当场报错，也不要默默少排一班、让你以为提醒已经生效。

班次名称随你习惯叫，中英文都行。

## 使用

### 先用插件页面（推荐）

装好之后，在 AstrBot 面板的插件页里打开 **明日方舟工具箱**，那个页面上能直接做这些事：

- **改班次**：拖时间轴调三个班的起止点（三段恒首尾相接、合计 24 小时，**拖不出非法配置**）
- **上传排班表**：选文件即可导入；旁边还有「**按排班表填入班次时长**」，一键把三班时长对齐到排班表
- **看状态**：当前班次、下一班倒计时、绑定目标、最近几条发送记录

### 绑定提醒

**私聊机器人**发一条：

```
/ak bind
```

把提醒绑定到当前会话。绑定之后到点就会收到提醒。

### 指令一览

| 指令 | 作用 |
| --- | --- |
| `/ak bind` | 把提醒发到当前会话（会覆盖之前的绑定） |
| `/ak status` | 看当前班次、下一班倒计时、最近几条发送记录 |
| `/ak test` | 立刻收一条测试提醒（不改动任何设置） |
| `/ak import <文件名>` | 导入排班表（用页面上传更方便，见下） |
| `/ak recruit [标签…]` | 公开招募计算，例如 `/ak recruit 输出 近战位`；不带标签会列出全部可填标签 |
| `/ak skland` | 森空岛授权状态（需先在配置里打开该模块） |
| `/ak skland login` | 扫码授权 |
| `/ak skland logout` | 清除本地授权 |
| `/ak skland check` | 测一次连接（顺带验证签名是否被服务端接受） |
| `/ak skland signin` | 立刻手动签到 |
| `/ak maa` | MAA 连上没有、队列里有什么、最近一次回报 |
| `/ak maa run` | 让它跑一次 |
| `/ak maa skip` | 这一班我自己换，不给 MAA 派任务 |
| `/ak maa cancel` | 撤掉待取任务 |

### 让提醒告诉你「换谁」（可选）

如果你在 [一图流基建排班生成器](https://riic.autos/) 之类的地方排过班，可以把导出的排班表喂给它，提醒里就会附上每个房间该上哪些干员——不然它只会告诉你「该换班了」。

排班表用的是 MAA 的基建排班格式（MAA 能导入的那种）。**推荐在插件页面上直接选文件上传**；也可以手动来：

1. 把导出的 `.json` 文件放进插件的数据目录
   （`/ak import` 用错文件名时会告诉你确切路径，找不到时直接照它给的路径放就行）
2. 私聊机器人发 `/ak import <文件名>.json`

导入成功会回执告诉你解析到几个班次、几个房间、几位干员。班次数量必须**正好 3 班**（跟插件配置一致），四班表会被拒绝并说明原因。

如果**排班表的班次时长与你在配置里填的顺序不一致**，导入回执会明确指出哪几班对不上——那意味着提醒里显示的房间与干员可能取自另一班。页面上有一键对齐的按钮。

> 排班表里被标了「不要动」的房间（MAA 里的 `skip`）**不会**出现在提醒里——那类房间的干员是会照常写着的，照着换反而是错的。

### 森空岛（可选，默认关闭）

先在插件配置里打开 `modules.skland`，然后发 `/ak skland login`：机器人会给你一张二维码，用**森空岛 App** 扫它并确认，授权就完成了。之后发 `/ak skland check` 可以验证一次连接。

**它会替你做的事**：每日签到。**签到是写操作**——会在你的游戏里产生实际效果，所以自动签到**另有独立开关，默认也是关的**；不打开就只能手动发 `/ak skland signin`。

**凭据**只存在插件自己的数据目录里，**不会写进日志**（日志里的扫码链接、凭据、绑定 uid 都是隐去或打码的）。授权会过期，过期后重新扫一次码即可。

> 干员疲劳、基建状态这类查询**没有实现**：那几条接口连存在性都没实测过，照着文档猜路径正是本项目吃过的亏，所以宁可不做。

### MAA 远程控制（可选，默认关闭）

这个功能让插件给你的 MAA 两个地址。配好之后你在 QQ 里发 `/ak maa run`，MAA 就在你电脑上跑一次，跑完汇报回来。

**到了换班时刻它会主动问你一次**（需要先把 `/ak bind` 设好通知目标）：「该换班了，要让它跑一次吗」——你回确认它才派任务。**它自己永远不会派**，队列在你确认之前一直是空的。不想跑就回一句"我自己换了"，本次就不会再问；不回答也算不跑。

**它的方向是反的**：不是你连 MAA，而是**你的 MAA 主动来问插件**。所以不用开端口、不用内网穿透。完整的接入步骤（含自签证书那一关怎么过）见 [MAA 接入指南](docs/guides/maa-remote-control.md)。

> ⚠️ MAA 每跑完一次基建任务，会把它内部的班次索引**永久前进一格**（写进配置、不会自动纠正）。所以**「派一次」等于「换一次班」**——本项目据此做了去重：同一次换班只允许一个任务，重复确认不会产生第二个。

### 关于权限

**私聊里任何人都能用**——绑定只影响你自己。

**群聊里只放开公开招募计算**（`/ak recruit`）：它是纯本地计算，不改动任何东西，而且只在有人问的时候才回话。

**其余指令在群聊里只限 AstrBot 管理员**：`/ak bind`、`/ak status`、`/ak test`、`/ak import`（这四个共用提醒模块的门禁）、`/ak skland`、`/ak maa`。理由很实际——`/ak bind` 会把换班提醒**推给全体成员**，`/ak test` 会往群里发一条提醒，`/ak import` 会改配置，`/ak skland` 会用到你的游戏账号，`/ak maa` 会真的让你电脑上的 MAA 跑起来。

**想自己收提醒、自己查状态，私聊发同一条指令就行——私聊不需要管理员。** 上面那句拒绝提示里也会告诉你这一点。

## 没收到提醒？按顺序查这几条

**先发 `/ak test`。** 这是最快的分诊：能收到，说明推送链路没问题，去查第 3 条；收不到，那就是第 1、2 条。

1. **有没有绑定过？** 发 `/ak status`，看「绑定」那一行。空的话发 `/ak bind`。
2. **机器人还在线吗？** 这是最常见的原因——QQ 号掉登录了（尤其服务器在境外、或号被多地登录时）。看 AstrBot 日志里有没有 `适配器已连接`，没有就是协议端掉了，去 NapCat 那边重新登录。
3. **班次时刻填对了吗？** 插件配置页里再核一遍：三段时长合计 24 小时，且首尾相接。填错的话插件不会加载定时任务，日志里会写明断在哪。
4. **提前量是不是比你想的大？** 比如提前 10 分钟，那 08:00 的班是 **07:50** 提醒，不是 08:00。
5. **是不是已经发过了？** 同一个班次的同一次换班**只提醒一次**（这是故意的，防重复）。插件重载也不会重复推。

还不行的话，把 AstrBot 日志里带 `ak_toolbox` 的行发出来。

## 几个已知的行为

- **同时只有一个提醒目标**。重新 `/ak bind` 会把它改到新的会话，不会两边都发。
- **没绑定时不会推送**，只在日志里记一条警告——不会静默地什么都不做。
- **连续推送失败**（比如机器人掉线）达到阈值后会**自动暂停**提醒，避免刷屏；推送成功一次就恢复。
- **发送记录**保留最近 50 条，`/ak status` 显示最近 5 条。

## 给开发者

架构、模块契约、如何新增一个功能模块，都在 [docs/architecture/](docs/architecture/)：

- [技术栈与约束](docs/tech-stack.md)
- [架构规则](docs/architecture/rules.md)（含「纯逻辑禁止 `import astrbot`」的原因）
- [模块基类契约与接入检查单](docs/architecture/extension.md)
- [实施记录与验收](docs/implementation/)

本地验证一条命令：

```bash
python scripts/verify_constitution.py && ruff check . && ruff format --check . && pytest -q && python scripts/check_room_colours.py && python scripts/check_astrbot_load_form.py
```

最后那条 `check_astrbot_load_form.py` 值得单独说一句：它按 **AstrBot 真实的加载形态**（插件被当包加载、顶层没有 `core`）在子进程里导入整个插件。这一类缺陷**本地普通测试看不见**——本项目为此吃过两次亏，其中一次是 695 条测试全绿、部署上去整个插件装不起来。

**关于网络请求**（AstrBot 规范要求「不要用 `requests`，可以用异步网络库」）：本项目**满足该要求的实质，但用了另一条路**。运行时**零第三方依赖**，网络走标准库 `urllib`；因为 `urllib` 是同步的，**所有调用点都包在 `asyncio.to_thread(...)` 里**，不会阻塞事件循环——效果与异步库相同，而不必把 `aiohttp`/`httpx` 写进依赖（它们虽然在 AstrBot 运行时里存在，但依赖别人的环境不是一件该赌的事）。其中「**全仓不出现 `requests`**」这一条有测试钉着（AST 扫描，`tests/test_network_policy.py`）；「**每个阻塞调用都经 `to_thread`**」目前靠代码审查维持，**没有机器护栏**——如实说明，不假装它被钉住了。
