# 最小架构范围（03a）

> 对应 skill 第 3 步第 1 小步：**只建支撑首个里程碑的最小范围**，不做全量功能。

## 1. 首个里程碑（M1）定义

| 项 | 内容 |
| --- | --- |
| M1 | 插件在服务器 AstrBot 里**加载成功**，用一条指令触发，手机收到一条**内容正确**的真实 QQ 提醒 |
| 不包含 | 到点自动触发、Pages 界面、森空岛、MAA、排班表导入 |
| 判据 | AstrBot 日志无报错 + QQ 实收 + `/ak status` 能打印下一班时刻 |

## 2. 最小架构 = 宿主 + 一个模块

```
宿主（core/）          只做四件事：读配置、装载模块、转发指令、转发定时
  └── 一个模块（modules/shift_reminder/）
        三班模型 · 时刻计算 · 消息渲染 · 推送 · 幂等
```

**宿主不许知道"三班"是什么。** 它眼里只有"模块"这个抽象——这条守住了，V2 加森空岛模块时才不用回来改宿主。

## 3. 为 V2 预留的三处接口（只留形状，不写实现）

| # | 插槽 | 今天的形态 | V2 谁填 |
| --- | --- | --- | --- |
| S1 | **模块基类** `core/module.py` | 定义一个模块必须有：`name`、配置 schema 片段、`initialize(context)`、`terminate()`、可选 `commands()` / `jobs()` | 所有后续模块 |
| S2 | **判定策略接口** | 只实现 `PeriodStrategy`（按三班时刻判定） | `MoraleStrategy`（森空岛心情），与周期策略同签名，调度层不感知 |
| S3 | **提醒附加段** | 渲染函数签名里留 `extra: list[str] \| None`，V1 恒为 `None` | 干员名单（排班表导入模块） |

> 留接口 ≠ 写空实现。V1 里这三处只体现为**函数签名与基类形状**，不出现"将来会用到"的分支代码。

## 4. 本期明确不做

| 不做 | 何时做 |
| --- | --- |
| 到点自动触发（依赖 cron_manager 的真实调度） | M2（同一 Phase，紧接着做） |
| Pages 页面 | V2 |
| 森空岛状态模块 | V2 |
| MAA 远程控制端点 | V2 |
| 排班表导入模块 | V2 |
| 多模块并存 | V2（届时验证"加模块不改老代码"这条是否成立） |
| 外部告警 | 不做（见技术栈 §10） |

## 5. 依赖方向（单向，禁止回指）

```
main.py  →  core/registry  →  modules/*
                ↓
             core/module (基类)
                ↓
             core/storage, core/config

纯逻辑层（modules/*/schedule.py, notify.py）不 import astrbot
```

**任何 `modules/` 下的代码都不许 import `main.py`；任何纯逻辑文件都不许 import `astrbot`。** 后者由 lint 规则强制（见 [rules.md](rules.md) §2）。
