## 1. 一句话价值主张

> 为我自己解决「换班时刻总被手头的事盖过去」的问题，在每次该换班时用 QQ 把「这是第几班、该换人了、下一班几点」送到手边，让我该上线时就能上线。

## 2. 真问题（5 Whys 收敛结果）

忘了换班不是因为记性差，而是因为**换班是固定的外部时间点，与当下的注意力无关**。手机闹钟只给时间、不给上下文，忙起来就被划掉。所以需要的不是「更多提醒」，而是「**在正确时刻、带上下文的一次提醒**」。

## 3. 形态：AstrBot 插件（v0.2 变更）

用户 2026-09-29 指示「直接做一个 AstrBot 插件」，并要求**具备开发潜力**。

| | 独立小服务（v0.1） | AstrBot 插件（**采用**） |
| --- | --- | --- |
| 发送通道 | 要给 NapCat 加 HTTP 端点、改配置、重启容器 | 复用 AstrBot 已连上的 QQ 号，`context.send_message(umo, chain)` 直接发，**零运维改动** |
| 运行时 | 额外进程 / systemd 单元 | 随 AstrBot 一起跑 |
| 配置界面 | 手改配置文件 | `_conf_schema.json` → WebUI 自动渲染表单 |
| 自定义界面 | 自己写前端 | `pages/` + `register_web_api()` → WebUI 内嵌页面 |
| 代价 | 解耦 | 与 AstrBot 版本耦合 → `astrbot_version` 约束 + 只用公开 API |

## 4. 调研结论：没有现成的轮子

- 拉取 AstrBot 官方插件市场索引，**1,332 个插件**全量匹配：「基建」「换班」「排班」「infrast」命中 **0**。
- 相关的 6 类插件（森空岛查询/签到、MAA 遥控、干员语音、Wiki 查询、理智提醒、通用定时器）**没有一个覆盖「三班换班时刻提醒」**。
- 可借鉴的三块：`astrbot_plugin_scheduler` 的调度写法、`astrbot_plugin_arknights` / `astrbot_plugin_skland` 的森空岛封装（V4 用）、官方插件上架规范。

→ **结论：要自己做**，详见 [00 市场调研](project-plan/00-market-scan.md)。

## 5. 核心目标

| 编号 | 目标 | 优先级 | 成功标准 |
| --- | --- | --- | --- |
| G1 | 换班时刻准时送达 | 必须 | 7 天 × 3 次 = 21 次，±60 秒内送达，漏报 0 |
| G2 | 提醒内容一眼看懂 | 必须 | 含班次名 + 换班提示 + 下一班时刻 |
| G3 | 业务规则可配置 | 应该 | 在 WebUI 插件配置里改提前量 / 三班 / 开关，不用改代码 |
| G4 | 自恢复、不重复 | 应该 | 插件重载与 AstrBot 重启后不重复推送，也不漏推 |
| G5 | 推送失败可见 | 应该 | 重试 + 失败写日志，可用一条指令查到 |

## 6. 范围边界

**V1 本期做**：插件骨架 → 配置项（三班/提前量/开关）→ 24h 校验 → 换班时刻计算（含跨天）→ 收件会话绑定与持久化 → 定时调度 + 主动推送 → 消息渲染 → 幂等去重 → 测试与状态指令 → 失败重试与日志 → 扩展点边界。

**不做**（逐条有理由）：独立服务/容器、代打游戏、遥控 MAA、网页前端、抓取 riic.autos、本期解析 MAA 排班 JSON、多用户、本期读森空岛、提醒回执、数据统计；灰区（要不要顺手做 V2 界面、要不要备选通道、要不要「今天跳过」）已逐条判定为不做。

**扩展路线图（开发潜力，本期只留位置不实现）**：

| 版本 | 能力 | V1 必须为它留出什么 |
| --- | --- | --- |
| V2 | WebUI 自定义页面（改三班、看倒计时、翻发送记录） | 配置读写与业务逻辑分离，能被 Web API 直接调用 |
| V3 | 从 riic.autos 导入排班表，提醒带干员名单 | 数据模型预留 `shift → rooms → operators`；提醒卡片可接受附加内容 |
| V4 | 森空岛读心情，真·「疲劳才换班」 | 触发判定抽成策略接口（周期策略 / 心情策略可互换） |

## 7. 可执行单元与里程碑

| 里程碑 | 单元 | 交付 |
| --- | --- | --- |
| **M1 骨架期** | U1–U5 | 插件装进 AstrBot，发一条指令，手机收到机器人**主动**发来的消息 |
| **M2 可用** | U6–U12 | 到点自动提醒；配置化；重载不重复；失败可见 |
| **M3 交付** | U13–U15 | 扩展点就位；README 与回滚齐备；7 天 21 次零漏报 |

风险前置五件事：① **服务器 AstrBot 是 4.28.1，官方文档可能对应更新版本**——`register_web_api` / `astrbot.api.web` 是否可用必须先验；② 插件重载后定时任务残留会重复推送；③ 机器人号与我的 QQ 是否好友；④ `umo` 绑定错会话；⑤ 插件目录与 data 目录混淆导致数据被覆盖。

## 8. 约束与风险

| 类别 | 内容 |
| --- | --- |
| 运行时 | 受 AstrBot 容器 Python 环境约束；新依赖必须写进 `requirements.txt` |
| 版本 | 目标 AstrBot **4.28.1**；`astrbot_version` 按实测可用范围填 |
| 资源 | 无新增进程、无新增端口 |
| 网络 | **不需要**动 NapCat / nginx / 安全组；不涉及 ADR-0004 的域名限制 |
| 合规 | 不代打、不注入、不抓取；V1 不接触游戏账号 |
| 公开 | 仓库公开，不得出现真实 QQ 号、IP、token |
| 回滚 | 停用或删除插件目录即可，不动 AstrBot 本体 |

## 9. 决策记录

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 为什么现在做 | 做 | 推送通道已跑通，边际成本极低；这是每天发生的固定损耗 |
| 形态：独立小服务 | ❌ v0.2 推翻 | 需要改 NapCat 配置并重启；插件形态全部免除 |
| 形态：AstrBot 插件 | ✅ 采用 | 复用发送通道与 WebUI 框架，零新增进程 |
| 形态：网页 / PWA | ❌ | 提醒终端本是 QQ；网页还受证书限制 |
| 是否重造轮子 | 已排除 | 1,332 个插件中无同类 |
| 排班来源：抓 riic.autos | ❌ | 需登录、无 API；V3 改为用户主动上传导出文件 |
| 疲劳驱动 vs 周期驱动 | 本期周期驱动 | 用户明确接受；只留策略接口 |
| 仓库 | 独立公开仓库，`astrbot_plugin_` 前缀 | 遵守官方命名约定 |
