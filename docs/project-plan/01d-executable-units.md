## 2. 风险前置项（先啃硬骨头）

| 风险 | 关联单元 | 为什么必须前置 |
| --- | --- | --- |
| **服务器上的 AstrBot 是 4.28.1，而官方文档可能对应更新版本** —— `register_web_api` / `astrbot.api.web` 这类较新的 API 可能不存在 | U3 | 如果 API 不可用，V1 的写法与 V2 的扩展路线都要改；这是整个方案的地基 |
| 插件重载后旧定时任务残留 → 同一班次被推两次 | U10 | 定时任务的生命周期归插件管理，重载/卸载必须清理；不处理就是"骚扰"而不是"提醒" |
| 机器人号与我的 QQ 不是好友 → 主动私聊发不出 | U5 | 走不通就要换方案（改群聊 / 换机器人号），越早暴露越好 |
| `umo` 拿不到或绑定错会话 → 消息发到别处 | U8 | 会话标识错了，提醒就成了噪音 |
| 插件目录与 AstrBot 数据目录混淆 → 插件更新后数据被覆盖 | U8 | 官方明确要求持久化数据放 data 目录 |

## 3. 里程碑

| 里程碑 | 包含单元 | 用户能看到什么 |
| --- | --- | --- |
| **M1 骨架期** | U1–U5 | 插件装进 AstrBot，发一条指令，手机收到机器人**主动**发来的消息 |
| **M2 可用** | U6–U12 | 到点自动提醒；配置化；重载不重复；失败可见；有状态与测试指令 |
| **M3 交付** | U13–U15 | 扩展点就位；README 与回滚齐备；跑满 7 天 21 次零漏报 |

## 4. 估算依据（S / M / L）

- **S**：单点动作，验证方式直接（装插件、发一条消息、填一次配置）
- **M**：涉及边界逻辑或跨组件协作，需要写测试（跨天计算、幂等、策略接口）
- **L**：必须等真实时间流逝才能验收（7 天周期）

## 5. 全局约束与风险汇总

| 类别 | 内容 |
| --- | --- |
| 运行时约束 | 插件随 AstrBot 容器运行，受其 Python 环境与依赖管理约束；新增依赖必须写进 `requirements.txt` |
| 版本约束 | 目标 AstrBot **4.28.1**；`metadata.yaml` 的 `astrbot_version` 按实测可用范围填写 |
| 资源约束 | 无新增进程、无新增端口；插件常驻内存应可忽略 |
| 网络约束 | 不需要改动 NapCat / nginx / 安全组；不涉及 [ADR-0004](../decisions/ADR-0004-tencent-domain-block.md) 的域名限制 |
| 合规约束 | 不代打、不注入、不抓取第三方站点；V1 不接触游戏账号 |
| 公开约束 | 仓库公开，代码与文档不得出现真实 QQ 号、IP、token |
| 运维约束 | 部署 = 插件目录落盘 + WebUI 启用；回滚 = 停用或删除插件目录（不动 AstrBot 本体） |
