## 2. 真问题模型（修订 [01a](01a-core-value.md) §2）

### 2.1 关键推论

「电脑不常开、服务器常开」这一句把架构钉死了：

```
调度与提醒  ──  必须长在【服务器】（常开，唯一 7×24 的节点）
执行换班    ──  发生在【游戏客户端】，可能在任何地方（手机 / 电脑 / 模拟器）
```

**推论 A：提醒不能依赖本机进程。** 服务器必须自己能算时刻、自己会发消息——这条把「AstrBot 插件」的形态彻底坐实（插件随 AstrBot 常驻服务器，不依赖用户电脑）。

**推论 B：执行端必须是"可选分支"而不是"前提"。** 用户电脑不在线时，提醒仍然要完整送达，并给出"自己手动换"的出口。

**推论 C：MAA 任务队列天然适配"时有时无"的客户端。** MAA 的远程控制是**客户端主动轮询**服务器领任务——电脑没开就没有轮询，任务在服务器排队；电脑上线后可以领走，或者因过期被丢弃。这比"服务器主动推送"更契合当前约束（服务器**不需要**连得通用户内网）。

### 2.2 修订后的一句话价值主张

> **为我自己解决「换班时刻总被手头的事盖过去」的问题：服务器在每次该换班时用 QQ 把「这是第几班、该换人了、下一班几点」送到手边；我顺手就能自己换，电脑正好开着时也能一句确认让它替我换。**

（原表述只覆盖"提醒"；修订后把"可选执行"纳入价值，但**执行绝不是前提**。）

## 3. 功能模型（修订 [01c](01c-feature-breakdown.md) §3）

### 3.1 三条路径

| 路径 | 触发条件 | 用户动作 | 依赖 |
| --- | --- | --- | --- |
| **A. 纯提醒**（保底路径） | 永远可用 | 收到消息 → 自己开游戏换 | 无（只要服务器在） |
| **B. 提醒 + 手动确认执行** | 电脑在线、MAA 在线 | 收到消息 → 回一句确认 → MAA 换班 → 收到结果（含截图） | MAA 客户端 + 远程控制协议 |
| **C. 全自动** | ⛔ 本期不做 | — | 会在用户不在线时贸然操作，且违反"可选"的定位 |

**硬约束：A 必须永远可用，B 的缺席不得影响 A。** 这是本次修订最重要的一条设计红线。

### 3.2 与「疲劳驱动」的关系

用户此前已确认：疲劳是本质，但不是硬约束。本期仍以**周期驱动**为主；接森空岛读心情（V3）之后，判定层可切换为"累了才推"，届时 A/B 两条路径不变（只换判定策略）。

## 5. 集成清单（回答 I3）

用户要求"集成这些关于明日方舟的插件"。按【能不能复制代码】分成三档——这是硬边界，不是偏好：

### 5.1 可以集成（MIT，允许复制实现）

| 插件 | 集成什么 | 方式 | 建议 |
| --- | --- | --- | --- |
| [`Siq5005/astrbot_plugin_arknights`](https://github.com/Siq5005/astrbot_plugin_arknights) | 森空岛取数：`core/skland.py` 的 `get_player_info`（返回含 `building` 段）+ `derive_sanity`，纯函数、注释完整 | **复制其取数/签名模块**并保留版权声明 | ✅ **首选**（比另一个更工程化） |
| [`Morizero1125/astrbot_plugin_arknights_skland`](https://github.com/Morizero1125/astrbot_plugin_arknights_skland) | 森空岛登录/cred 刷新/理智提醒/卡片渲染的整套 `skland/` 包 | **复制所需的子模块**并保留版权声明 | ✅ 备选（体量大，按需取用） |
| [`Justice-ocr/astrbot_plugin_mimo_tts_clone`](https://github.com/Justice-ocr/astrbot_plugin_mimo_tts_clone) | Pages 页面 + 文件上传的骨架 | 复制结构 | ✅ 用于 V2 的排班表导入界面 |

### 5.2 只能协议级复用（AGPL，**代码一行不能进**）

| 插件 | 能拿什么 | 为什么不能复制 |
| --- | --- | --- |
| [`Hakuin123/astrbot_plugin_maa`](https://github.com/Hakuin123/astrbot_plugin_maa) | **MAA 远程控制的协议行为**：它是 HTTP 服务端，暴露 `/maa/getTask` 与 `/maa/reportStatus`，由 MAA 客户端轮询 | AGPL-3.0 传染：一旦复制，整个插件必须也按 AGPL 开源 |

→ **做法：按 MAA 官方[远程控制协议](https://docs.maa.plus/zh-cn/protocol/remote-control-schema.html)自己实现这两个端点**，不读它的代码。上游协议本身是公开规格。

### 5.3 明确不集成

| 类别 | 例子 | 原因 |
| --- | --- | --- |
| 无 LICENSE 文件的仓库 | `Azincc/astrbot_plugin_skland`、`qihang518887/astrbot_plugin_sklandv2` | 法律上默认不可复制（README 自称 MIT 不构成授权） |
| 与本需求无关的方舟插件 | 角色语音、抽卡查询、PRTS 资料、公招 OCR、通行证抽奖 | 与"换班提醒"没有功能交集 |
| 终末地相关 | `astrbot_plugin_endfield` | 不同游戏；且是 AGPL |
| 会引入账号风险的能力 | 代打、注入、代签 | 触碰游戏用户协议 |

> ⚠️ **本项目的许可证策略**：为保持"可自由选择开源协议"的空间，**不引入任何 AGPL 代码**。需要其能力时，按公开协议自己实现。
