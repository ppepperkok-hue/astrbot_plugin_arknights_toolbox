# 定位修订 02：这不是「换班提醒插件」，是「明日方舟助手插件」

- **时间**：2026-09-29
- **触发**：用户指出「边界还是错了，既然都集成了其他插件，提醒换班只是一个功能」
- **性质**：**定位级修正**，取代 [01a-core-value.md](01a-core-value.md) 的 §1–§6 与 [01c-feature-breakdown.md](01c-feature-breakdown.md) 的 §1–§4 中把"换班提醒"当作项目本体的所有表述。

---

## 1. 错在哪

前一版把项目定义成「换班提醒插件」，把「集成方舟插件」写成"顺带的扩展"。用户指出这是主次颠倒：

> **既然要集成的是一整套明日方舟能力，那"提醒换班"就只是这个插件里的一个功能，不是它的全部。**

两者的差别不是措辞，是架构：

| | 旧定位（错） | 新定位（对） |
| --- | --- | --- |
| 项目是什么 | 换班提醒，附带一些方舟集成 | **明日方舟能力工具箱** |
| 提醒换班的地位 | 项目本体 | **第一个功能模块** |
| 集成机制 | 附加项，能加就加 | **宿主骨架的一部分**——没有它，项目就只是个小工具 |
| 扩展方式 | 往主流程里加分支 | **加一个模块，互不影响** |
| 名字 | `..._shift` （以功能命名） | 应以**领域**命名，不以首个功能命名 |

## 2. 修正后的定位

> **一句话**：把我的明日方舟日常收进一个 AstrBot 插件——基建换班提醒、森空岛状态、排班表管理、可选的本机 MAA 触发……每个能力是一个可单独开关的模块，服务器常开就一直在。

- **用户**：本人（一个人用，不做多用户）
- **载体**：AstrBot 插件（随 AstrBot 常驻服务器）
- **首个模块**：基建换班提醒（三班可配置、到点 QQ 推送、保底路径零外部依赖）
- **后续模块**：按需加，加一个不影响已有的
- **红线**：不复制 AGPL / 无 LICENSE 仓库的代码；不做游戏内注入或代打

## 3. 架构含义：宿主 + 模块

定位一变，骨架就得变——从"一条主流程"变成"一个宿主 + 若干可插拔模块"：

```
astrbot_plugin_arknights_toolbox/
├── main.py                  # 宿主：读配置，装载启用中的模块
├── metadata.yaml
├── _conf_schema.json        # 每个模块一组开关与配置
├── core/
│   ├── module.py            # 模块基类：生命周期 / 配置 / 命令 / 定时任务
│   ├── registry.py          # 模块注册表
│   └── storage.py           # 统一持久化（plugin_data + 官方 KV）
├── modules/
│   └── shift_reminder/      # 【V1】基建换班提醒
│       ├── module.py
│       ├── schedule.py      # 三班模型 + 时刻计算（纯函数，可单测）
│       └── notify.py        # 消息渲染 + 推送 + 失败熔断
└── webui/                   # 【V2】Pages 页面（无构建链）
```

**收益**：V1 只装一个模块时，它跟"小工具插件"没区别；但加第二个模块时**不需要动 V1 的代码**——这正是用户要的"集成能力"。

**代价**：多一层抽象。但模块数 ≥2 之后就开始回本，而本项目的路线图上明确有 ≥4 个模块。

## 4. 模块路线（不是功能清单，是模块清单）

| 模块 | 状态 | 依赖 | 说明 |
| --- | --- | --- | --- |
| `shift_reminder` 基建换班提醒 | **V1 必做** | 无（保底路径零外部依赖） | 三班可配置、到点推送、幂等 |
| `skland` 森空岛状态 | V2 | 森空岛 API + MIT 取数实现 | 基建一览 / 干员心情 / 理智；也是"疲劳驱动"的数据源 |
| `maa` 本机 MAA 触发 | V2 | MAA 官方远程控制协议 | 电脑在线时替我们跑一次换班 |
| `schedule_import` 排班表导入 | V2 | WebUI Pages | 吃 riic.autos 导出的 MAA JSON，让提醒带上干员名单 |
| 其他 | 按需 | — | 只要不违反红线，加模块不改老代码 |

模块之间的唯一耦合点：**"疲劳驱动"是 `skland` 给 `shift_reminder` 提供的一种判定策略**——通过 `core/module.py` 定义的策略接口解耦，而不是互相 import。

## 6. 命名

以**领域**命名，不以首个功能命名：

- ~~`astrbot_plugin_arknights_shift`~~ → **`astrbot_plugin_arknights_toolbox`**

理由：叫 `..._shift` 的话，以后加了森空岛、加了 MAA 触发，名字就撒谎了；`toolbox` 与"宿主 + 模块"的定位一致。已发布的旧仓库名通过 GitHub 重命名保留 301 重定向。
